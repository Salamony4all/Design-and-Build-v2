## 6. Door Style-Field Interpretation

From `evidence/code06/door-style-capture.json`:

| Field | Raw Value | Normalized Value | Present in Source | Default Applied | Meaning |
|---|---|---|---|---|---|
| sw0 | `sw0` | strokeWidth = 0 (hairline) | Yes (explicitly 0) | No | Hairline stroke rendering |
| rgbnone | `rgbnone` | no explicit RGB colour object | No (absent from PDF operator) | Yes (fallback to default ink) | No colour object attached; renderer applies default black ink |
| f0 | `f0` | fill = none | No (absent from PDF operator) | Yes (not present) | No fill operation in the stroke path |
| c0 | `c0` | clipping group = none | Yes (explicitly none) | No | No clipping path active |

**Key insight:** `rgbnone` means "no colour object was attached to this stroke path" — the renderer falls back to its default ink colour (black). It does NOT mean the colour data was discarded or that the render state is missing. The door convention intentionally uses implicit black ink with no fill and hairline stroke width.
